## Stack

Published TypeScript library. `tsc` only build, no bundler. ESM, `"type": "module"`. Runtime-neutral: no `node:*` imports in `src/` by default - consumers run it in Node, the browser, Bun, Deno, or workers. Vitest for tests. Changesets for versioning and publishing. Optional CLI surface via `bin` (delete that section if not a CLI).

## Commands

Toolchain: Node 26 + pnpm 12, pinned in `mise.toml`. Run `mise install` once.

```
mise run install       # pnpm install
mise run typecheck     # tsc --noEmit
mise run lint          # Biome or ESLint
mise run build         # tsc -p tsconfig.build.json -> dist/
mise run test          # Vitest
mise run changeset     # record an upcoming user-facing change
mise run version       # changeset version (bumps + CHANGELOG)
mise run release       # build && changeset publish
mise run check         # typecheck + lint + test
```

Cite exact script scope. Do not claim a command runs every test unless `package.json` proves it.

## Standards

- Strict TypeScript, ESM-first. `"type": "module"`.
- **Public surface** lives in `src/index.ts`. Anything not re-exported there is private - deep imports are not part of the contract.
- `package.json` ships an `"exports"` map (single entry by default) plus `"types"` pointing at `dist/index.d.ts`, and `"sideEffects": false` so consumers can tree-shake.
- No `node:*` imports in `src/` (CLI file exempt - see `.context/guides/engineering.md`). Prefer standard ECMAScript APIs. Use `globalThis`, not `window` or `global`.
- No `process.env`, `process.cwd`, or filesystem reads in library code. Configuration is taken as a function argument or constructor option. The host owns env.
- No logger. Throw on error, return on success - the consuming app owns logging.
- Public API is fully typed: `.d.ts` shipped from `dist/`. No `any` except at one isolated SDK boundary with a comment.

## Safety

Do not read `.env`, `.secrets`, certs, tokens, DSNs, cloud credentials. Do not commit `.npmrc` containing auth tokens. Full list in `.context/guides/engineering.md`. Use `.env.example` for variable names only (rare for libraries).

Search scope, "no settings" rule, and commit/changeset style live in [`.context/guides/engineering.md`](.context/guides/engineering.md).

## Where To Edit

| File | Owns |
|---|---|
| `src/index.ts` | Public surface. Only re-exports - no inline implementation. |
| `src/*.ts` | Internal modules. Importable here but not part of the contract. |
| `src/__tests__/` | Vitest unit tests. Mirror source layout. |
| `src/cli.ts` | (Optional) CLI entry. Only file allowed to import `node:*`. |
| `package.json` | `exports`, `types`, `bin`, `files`, `sideEffects`, scripts. |
| `tsconfig.json` / `tsconfig.build.json` | Strict TS config + emission config. |
| `mise.toml` | Toolchain pins and task entrypoints. Commands in this file map 1:1 to its tasks. |
| `vitest.config.ts` | Test runner config. |
| `.changeset/` | Pending release notes. One file per user-facing change. |
| `CHANGELOG.md` | Generated by `changeset version`. Do not hand-edit released entries. |
| `.context/` | Durable architecture, decisions, debt. |
| `AGENTS.md` | This file. Keep compact; push detail into `.context/`. |

## Maintenance

Update commands here when `package.json` scripts change. Update `.context/project-context.md` when the public surface changes shape. Record durable decisions (supported runtimes, CJS stance, peer-dep strategy) in `.context/project-context.md`. Every user-facing change ships a `.changeset/` entry alongside the code.
